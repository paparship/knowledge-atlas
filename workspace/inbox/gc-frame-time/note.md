**垃圾回收（GC）**由运行时识别并回收程序已经无法访问的对象。

**可达**指从全局变量、当前调用栈中的局部变量等起点，能沿着引用找到某个对象。例如 Lua GC 顺着「全局游戏状态 → 当前棋盘 → 掉落动画 → 轨迹表」逐个标记对象，这就是追踪。动画结束后，棋盘移除对动画的引用；如果没有其他路径通向动画或轨迹表，两者就都可以回收，即使动画内部仍引用着轨迹表。

**卡顿来自回收工作占用了这一帧的时间。** GC 要追踪仍然可达的对象、清理垃圾；如果这部分工作在主线程执行，游戏逻辑和画面提交就要等它。以 60 FPS 为例，一帧约有 16.7 ms；原本耗时 14 ms 的帧再做 5 ms 回收，就可能错过下一次刷新。

回收时机需要权衡**内存峰值**与**单帧耗时**。在《开心消消乐》的迁移案例中，JS 和 Lua 各自管理自己的堆；团队在内存压力较大的 iOS 设备上定时触发 Lua GC，在部分低性能安卓机上按局安排回收。判断策略是否有效，要同时看连续游玩时的内存峰值和回收发生时的帧耗时。
