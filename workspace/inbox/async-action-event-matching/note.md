异步动作与事件匹配，是通过一次调用的唯一标识，将动作发起、完成事件和后续等待关联起来，使流程在对应动作完成后继续执行。

## 从同时执行两个动作开始

一段演出中，守卫 A 走到门口，守卫 B 走到玩家旁边；两人同时移动，等 B 到位后开始对话。

```text
call 移动守卫 A 到门口
call 移动守卫 B 到玩家旁边
gate 等待守卫 B 的这次移动完成
call 开始对话
```

两个 call 分别发起移动，运行器继续执行到 gate，在这里等待 B 到位。

## 用调用 ID 关联动作与结果

两个动作都会产生“移动完成”事件；等待条件需要指出它对应哪一次调用。

为每次 call 生成唯一的调用 ID，并交给执行动作的游戏能力；动作完成后，事件带回这个 ID，gate 按 ID 匹配结果。

```text
a = call 移动守卫 A 到门口        → callId = move-101
b = call 移动守卫 B 到玩家旁边    → callId = move-102
gate 等待 b 完成                 → 等待 move-102
call 开始对话
```

这里 a、b 是本次运行中调用结果的引用，gate 通过 b 取得实际的调用 ID。

即使两个结果按不同顺序返回，也按 ID 分别处理：

| 收到的事件 | gate 等待的调用 | 处理 |
| --- | --- | --- |
| move-101 完成 | move-102 | 保存 A 的结果，继续等待 B |
| move-102 完成 | move-102 | 匹配成功，继续执行对话 |

一次移动的调用与完成事件可以表示为：

```json
{
  "callId": "move-102",
  "action": "move",
  "args": { "npcId": "guard-B", "target": "player-side" }
}
```

```json
{
  "callId": "move-102",
  "event": "completed"
}
```

**节点 ID 标识配置中的一个节点，调用 ID 标识运行时的一次执行。** 同一节点再次执行时，产生新的调用 ID，结果仍能对应到各自的那次调用。

## 结果先于等待到达

如果 B 很快到位，完成事件可能在运行器进入 gate 前到达；匹配机制同时保存“已到达的结果”和“正在等待的调用”。

```text
gate 开始等待 callId：
    已有结果 → 取走结果，继续执行
    暂无结果 → 登记等待

完成事件到达：
    已有对应等待 → 交付结果，唤醒 gate
    暂无对应等待 → 按 callId 暂存结果
```

这样，无论是先等待还是先完成，都通过同一个调用 ID 汇合。
