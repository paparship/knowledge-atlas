C++ 常用 STL 容器分为顺序容器、关联容器和容器适配器；底层存储结构决定了访问、查找、插入、删除与遍历的成本。

## 顺序容器

| 容器 | 底层结构 | 优势 | 主要成本 |
|---|---|---|---|
| vector | 连续内存的动态数组 | 下标访问 O(1)，遍历缓存友好，尾部插入均摊 O(1) | 中间插删 O(n)，扩容需要搬迁元素 |
| deque | 通常由多段数组和管理各段的索引构成 | 下标访问 O(1)，头尾插删 O(1) | 内存不整体连续，中间插删 O(n)，索引访问有额外间接寻址 |
| list | 双向链表 | 已知位置时插删 O(1)，其他元素的位置稳定 | 查找 O(n)，不支持下标访问，指针和节点分配开销较大，缓存利用率低 |
| forward_list | 单向链表 | 比双向链表少一个指针，已知前驱时插删 O(1) | 只能向前遍历，查找 O(n) |
| array | 固定长度的连续数组 | 下标访问 O(1)，无扩容开销 | 长度在编译期确定，不能动态增减 |

vector 的尾部插入“均摊 O(1)”是指：多数插入只写入一个元素，偶尔扩容需要搬迁已有元素，多次操作的成本平均下来为 O(1)。

deque 是 double-ended queue，即双端队列，可以高效地从头部和尾部插入、删除。其常见实现通过索引管理多段数组，两端增长时通常只需增加数据块，无须像 vector 扩容那样搬迁全部元素。

## 关联容器

| 容器 | 底层结构 | 优势 | 主要成本 |
|---|---|---|---|
| map / set | 通常为红黑树 | 查找、插入、删除 O(log n)，按键有序，支持上下界与范围查询 | 节点及指针有额外存储开销，缓存利用率较低 |
| unordered_map / unordered_set | 哈希表 | 查找、插入、删除平均 O(1) | 无序，最坏 O(n)，重新哈希有成本 |

- map 存储键值对，例如“玩家 ID → 玩家对象”；set 存储键，例如“已领取奖励的玩家 ID”。
- multimap、multiset 允许重复键，也有对应的 unordered_multimap、unordered_multiset。

## 容器适配器

容器适配器基于已有容器提供受限制的操作接口，表达栈、队列和优先队列。

| 适配器 | 默认底层 | 行为与操作成本 |
|---|---|---|
| stack | deque | 后进先出，压栈、出栈和查看栈顶 O(1) |
| queue | deque | 先进先出，入队、出队和查看队首 O(1) |
| priority_queue | vector 上维护二叉堆 | 默认最大值优先，查看堆顶 O(1)，插入与弹出 O(log n) |

## 按访问方式选择

| 主要需求 | 常用选择 |
|---|---|
| 普通列表、频繁遍历或下标访问 | vector |
| 长度固定的数组 | array |
| 两端频繁增删，同时需要下标访问 | deque |
| 已持有节点位置，频繁插删或拼接链表 | list |
| 按键查找，不要求顺序 | unordered_map / unordered_set |
| 按键排序、上下界或范围查询 | map / set |
| 后进先出或先进先出 | stack / queue |
| 反复取当前优先级最高的元素 | priority_queue |

list 的 O(1) 插删以已经找到位置为前提；如果每次都需要遍历寻找目标，整次操作仍为 O(n)。
