> 计算机网络 / HTTP

**HTTPS 是通过 TLS 保护的 HTTP，通过验证服务器身份、加密数据和校验完整性，防止传输中的窃听、篡改及服务器冒充。**

下面以浏览器首次访问 `https://shop.example.com`、使用证书完成 TLS 1.3 握手为例。

## 连接前：双方已经有什么

商城服务器保存证书和对应私钥。证书颁发机构（CA）核验网站的域名控制权后签发证书，将 `shop.example.com` 与网站的公钥绑定；网站保管私钥，用它生成签名，浏览器通过配对的公钥验证。

浏览器或操作系统预先保存受信任的根证书，作为验证证书链的起点。

## ① 交换公开材料，算出共享秘密

**浏览器 → 服务器：**“我支持这些 TLS 参数，这是我为本次连接生成的公开密钥交换材料。”

**服务器 → 浏览器：**“使用这组参数，这是我的公开密钥交换材料。”

双方各自结合自己的秘密数据与对方的公开材料，算出相同的共享秘密，并派生出握手阶段的加密密钥。网络上传输的是公开材料，共享秘密由双方分别计算得到。

## ② 服务器在加密通道里证明身份

**服务器 → 浏览器：**“这是我的证书链，以及我用证书对应的私钥对本次握手记录生成的签名。”

这一步的证书和签名已经加密传输，浏览器用刚才派生的握手密钥解密。

## ③ 浏览器验证：加密连接的对方是谁

- **验证证书链、域名和有效期**：确认受信任的 CA 认可证书中的公钥与 `shop.example.com` 的绑定。
- **验证本次握手签名**：用证书里的公钥检查签名，确认当前对方持有对应私钥，且签名覆盖的握手内容与浏览器的记录一致。

到这里，浏览器确认刚才与自己建立共享秘密的，是目标域名授权的服务器；签名将服务器身份与这次密钥交换绑定起来。

## ④ 确认握手，发送 HTTP 请求

双方验证握手完成消息，并派生出用于应用数据的密钥，与握手阶段使用的密钥分开。

**浏览器 → 服务器：**发送加密后的 `GET /orders` 请求。

**服务器 → 浏览器：**解密并处理请求，返回加密后的订单响应。

浏览器解密响应，再把内容交给页面使用。
