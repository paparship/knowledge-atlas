> 计算机网络 / HTTP

**同源策略限制网页脚本读取其他源的数据，CORS 通过服务端声明，让指定来源的网页获得跨域访问许可。**

## 同源如何判断

源由协议、域名和端口组成，三者都相同才是同源；路径和查询参数不影响判断。

以 `https://www.example.com/orders` 为基准：

| 另一个地址 | 是否同源 | 原因 |
| --- | --- | --- |
| `https://www.example.com/profile` | 同源 | 只有路径不同 |
| `https://www.example.com/orders?page=2` | 同源 | 只有查询参数不同 |
| `http://www.example.com/orders` | 不同源 | 协议不同 |
| `https://api.example.com/orders` | 不同源 | 子域名不同 |
| `https://example.com/orders` | 不同源 | 域名不同 |
| `https://www.example.com:8443/orders` | 不同源 | 端口不同 |
| `https://www.example.com:443/orders` | 同源 | HTTPS 默认端口为 443 |

## 跨域限制保护什么

用户登录银行网站后，又打开其他网站，同源策略限制后者的脚本**读取**银行**响应**中的余额、交易记录等数据。

这里要区分两个阶段：请求是否可以发送，以及响应是否可以交给页面脚本读取。浏览器对**部分请求先检查发送许可**，对跨域响应再检查读取许可。

## 业务中如何配合

商城前端位于 `https://shop.example.com`，订单 API 位于 `https://api.example.com`。API 服务端配置允许商城来源、需要的方法和请求头，并在响应中返回对应的 CORS 头；例如 `Access-Control-Allow-Origin: https://shop.example.com` 表示允许该商城页面读取响应。

当请求需要预检时，流程是：

- 浏览器发送 `OPTIONS`，告知来源、准备使用的方法和请求头。
- 服务端返回允许范围，浏览器检查通过后发送实际请求。
- 实际响应返回时，浏览器检查其中的 CORS 允许头，再将结果交给页面脚本。

JSON 正文、身份凭证请求头等现代 API 常见用法会涉及预检，浏览器负责判断并自动执行；开发时重点保证服务端和网关能正确处理 `OPTIONS`，并让实际响应携带相应的 CORS 头。

## 如何排查

在浏览器 Network 中按请求阶段定位：

- **预检失败**：查看 `OPTIONS` 是否被网关或认证中间件拦截，以及返回的允许范围是否匹配请求。
- **实际响应被限制读取**：检查实际响应，包括错误响应，是否携带正确的 CORS 允许头。
- **接口本身失败**：根据实际请求的状态码、响应和服务端日志排查业务问题。

CORS 管理网页来源的访问许可；用户是谁、能操作哪些订单，由接口的认证与权限检查负责。
