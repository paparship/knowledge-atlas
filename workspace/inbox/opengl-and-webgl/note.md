OpenGL 和 WebGL 都是图形接口。应用可以通过它们把顶点、纹理和绘制指令交给图形系统，由 GPU 计算并生成画面。

| 接口 | 在哪里用 | 典型场景 |
|---|---|---|
| **OpenGL** | 原生应用的渲染代码，或游戏引擎的渲染后端 | 桌面游戏、模型查看器、可视化工具 |
| **WebGL** | 网页通过 JavaScript 获取 HTML `<canvas>` 的 WebGL 绘图上下文 | 在线模型预览、网页游戏、三维地图 |

WebGL 的接口设计基于 OpenGL ES，由浏览器提供给网页使用。

## 应用代码怎样用到它们

以网页模型预览为例。用户拖动鼠标时，应用代码根据输入改变相机位置。用 Three.js 这类渲染库时，应用把场景和相机交给渲染器，渲染器通过 WebGL 提交绘制，GPU 算出新画面，浏览器把它显示在画布上。

```text
鼠标拖动 → 应用更新相机 → 渲染库调用 WebGL → GPU 绘制 → 画布显示
```

原生游戏里也是类似的分工。游戏逻辑更新角色位置，引擎根据当前场景组织绘制。如果渲染后端采用 OpenGL，引擎就通过 OpenGL 把模型、材质所需的数据和绘制命令交给图形系统。

做交互和业务功能时，通常操作的是场景、模型和相机。自己实现渲染器时，才会直接处理图形接口里的顶点缓冲、纹理、着色器和绘制调用。
