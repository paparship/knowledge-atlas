伪随机数生成器从种子初始化内部状态，按固定算法更新状态并产生输出；相同的算法、种子和调用顺序会得到相同序列。

## 1. 线性同余法（LCG）

只保存一个整数状态，每次做乘加取模，再把结果作为新状态和输出。

```text
下一状态 = (a × 当前状态 + c) % m

例如 a = 5、c = 1、m = 16，种子为 3：
(5 × 3 + 1) % 16 = 0
(5 × 0 + 1) % 16 = 1
(5 × 1 + 1) % 16 = 6

序列：3 → 0 → 1 → 6 → 15 → … → 3
```

这个例子经过 16 步回到原状态，之后整段序列重复，周期为 16；虽然 0～15 都会出现，奇偶却严格交替，连续输出之间有明显规律。

**适用场景**：简单、资源受限且对统计质量要求不高的随机过程，或理解伪随机机制；优点是快、省空间，取舍是参数敏感，低位和连续输出可能有明显相关性。

## 2. Xorshift

保存一个非零状态，依次对它做固定的移位与异或运算，最后的结果既作为输出，也留作下一次调用的状态。

一个经典的 32 位版本如下，每步只保留低 32 位：

```text
x = 当前状态
x = x XOR (x 左移 13 位)
x = x XOR (x 右移 17 位)
x = x XOR (x 左移 5 位)
保存 x，并输出 x

种子为 1 时：1 → 8193 → 8193 → 270369
本次输出 270369，下次从 270369 开始重复上述步骤。
```

这个版本使用非零种子时，周期为 2³²−1；13、17、5 是选定的参数组合，零状态会一直产生零。

**适用场景**：需要小状态、低计算开销的一般游戏随机过程或轻量模拟；优点是状态小、计算快，基础版本存在位级线性规律。

## 3. PCG

将“更新状态”和“生成输出”分开：内部用线性同余法推进状态，对外输出前再进行变换。

以常见的 PCG32 XSH-RR 为例：

```text
① 记录旧的 64 位状态 old。
② 更新状态：
   state = (old × 6364136223846793005 + 奇数增量) % 2⁶⁴
③ 生成待输出的 32 位数：
   bits = 取低32位(((old 右移18位) XOR old) 右移27位)
④ 从 old 的最高5位取得旋转位数，范围为 0～31。
⑤ 将 bits 按这个位数循环右旋，得到本次输出。
```

状态递推决定序列如何前进，输出变换改善直接输出同余状态时的统计性质；PCG32 每条流的状态周期为 2⁶⁴。

**适用场景**：游戏随机、程序化生成和一般模拟，需要兼顾速度、较小状态和统计质量时；固定种子与流参数可以复现序列。

## 4. 梅森旋转算法（MT19937）

MT19937 保存一个包含 624 个整数的状态数组，每个整数占 32 位。state[0]、state[397] 表示数组中的第 0、397 个位置，每个位置都保存一个完整整数。

生成过程分为两阶段：**先更新整个状态数组，再依次从数组中取值生成输出。**

### 第一阶段：更新整个状态数组

更新一个位置时，需要用到三个位置的数据。例如更新 state[0]，就使用 state[0]、state[1] 和 state[397]。

```text
更新位置 0：
    从 state[0] 和 state[1] 拼出临时数 y
    将 y 与 state[397] 按更新公式运算
    结果写回 state[0]

更新位置 1：
    从 state[1] 和 state[2] 拼出临时数 y
    将 y 与 state[398] 按更新公式运算
    结果写回 state[1]

更新位置 2：
    从 state[2] 和 state[3] 拼出临时数 y
    将 y 与 state[399] 按更新公式运算
    结果写回 state[2]

……依次处理到位置 623，索引超过 623 就绕回开头……
```

这里采用顺序原地更新：结果直接写回数组，后续索引绕回时会读到本轮已经更新的位置。例如，更新位置 227 时，第三个位置是 (227 + 397) % 624 = 0，读取的是已更新的 state[0]。

每个位置使用相同的更新规则；以位置 0 为例：

```text
① 取 state[0] 的最高 1 位，拼上 state[1] 的低 31 位，得到 y。
② 计算 result = state[397] XOR (y 逻辑右移 1 位)。
③ 如果 y 的最低位为 1，再令 result = result XOR 0x9908B0DF。
④ 将 result 写回 state[0]。
```

因此，y 只是这一次更新使用的临时拼接值，更新结果保存在数组中；624 个位置全部处理完，就得到下一批供输出使用的状态。

### 第二阶段：依次取状态，生成输出

```text
第一次取数：x = 更新后的 state[0] → 输出变换 → 返回结果
第二次取数：x = 更新后的 state[1] → 输出变换 → 返回结果
第三次取数：x = 更新后的 state[2] → 输出变换 → 返回结果
……
第 624 次取数：x = 更新后的 state[623] → 输出变换 → 返回结果

这批用完，再更新整个数组，开始下一批。
```

这里的 x 是从数组取出的副本，对它依次做下面四步运算，每步保留低 32 位：

```text
x = x XOR (x 逻辑右移 11 位)
x = x XOR ((x 左移 7 位) & 0x9D2C5680)
x = x XOR ((x 左移 15 位) & 0xEFC60000)
x = x XOR (x 逻辑右移 18 位)
返回 x
```

输出变换不写回数组。**y 用于计算新状态，x 用于从新状态计算输出；两者通过状态数组连接起来。**

MT19937 的固定参数经过数学设计，使状态周期达到 2¹⁹⁹³⁷−1，并具有良好的多维均匀分布性质；保存状态约需 2.5 KB。

**适用场景**：一般科学模拟、蒙特卡洛采样，以及需要复现既有 MT 随机序列的程序；取舍是状态比前几种方法大，仍存在可分析的线性结构。

## 5. 拓展：密码学安全随机数与物理随机源

**密码学安全随机数**：前面的算法主要关注分布、周期和生成速度；这一类还要求别人即使看到已有输出，也难以预测接下来的数字。因此，生成登录令牌、密码重置链接或密钥时，需要使用操作系统或语言提供的安全随机接口，防止别人猜出这些凭证。

**物理随机源**：从电路噪声等真实物理现象中采集随机信息，为随机数生成器提供种子。它负责提供新的随机信息，软件生成器负责高效地产生后续数字，两者通常配合使用。
