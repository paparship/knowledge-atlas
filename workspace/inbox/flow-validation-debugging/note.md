配置校验与调试，通过运行前检查配置、记录执行过程和展示当前状态，帮助发现配置错误并定位流程停滞的原因。

## 配置校验：运行前发现错误

加载配置时检查字段、参数类型、动作名称、节点与资源引用，以及图中节点的可达性。

例如节点 N2 的 next 指向不存在的 N9，校验结果应指出具体位置：

```text
节点 N2 · 字段 next：目标节点 N9 不存在
```

## 执行日志：串起发生过的过程

runId 标识一次剧情执行，callId 标识其中一次动作调用；从发起、等待到结果回传，相关日志携带同一组标识。

```text
run=R1  call=C1  节点 N1：发起移动 A
run=R1  call=C2  节点 N2：发起移动 B
run=R1  call=C2  节点 N3：gate 开始等待
run=R1  call=C1  移动 A 完成
run=R1  call=C2  移动 B 完成
run=R1  call=C2  节点 N3：gate 放行
```

按 runId 筛选这次剧情，再按 callId=C2 筛选，就能连起“发起 B → 等待 B → B 完成 → 放行”；日志同时记录时间和结果，便于查看先后顺序、耗时与失败原因。

## GM 面板：查看当前停在哪里

面板读取运行时状态，高亮当前节点，并展示等待条件、关联调用及相关系统的状态，例如：

| 项目 | 当前值 |
| --- | --- |
| 剧情执行 | R1 |
| 当前节点 | N3：gate |
| 等待调用 | C2：移动 B |
| 调用状态 | pending |
| 移动系统状态 | 正在前往目标位置 |

排查时先在面板找到等待中的调用，再用相同的 runId、callId 查看日志：动作尚未完成就检查执行系统，动作已完成却没有结果记录就检查回传，结果已收到但 gate 未放行就检查匹配与唤醒。
