排查页面卡顿，先复现一次具体的用户操作，找出时间花在哪一步，再决定改哪里。

以搜索列表为例：输入文字立即出现，但结果迟迟没有返回，先看浏览器 **Network** 面板里的请求耗时；如果连输入的文字都过一会儿才显示，就用 **Performance** 面板录下这次输入，查看按键到页面更新之间，哪段 JavaScript、布局或绘制花的时间最长。

| 观察到的现象 | 常见原因与处理 |
| --- | --- |
| 切换一个开关，整张结果列表也跟着渲染 | 在 **React DevTools Profiler** 录下这次更新，看哪些组件渲染、各自耗时多久。如果开关状态只有局部使用，就把状态移到使用它的组件；列表组件开销大且 props 稳定时，可用 `memo` 跳过这次渲染。 |
| 切换主题时，又对同一份列表执行了昂贵的筛选 | 用 `useMemo` 保存筛选结果。列表和关键词都没变时，可以直接复用。 |
| 渲染几千行后，滚动时布局和绘制耗时明显 | 用虚拟列表只渲染可见行及其附近少量行，减少浏览器要维护的页面元素。 |

```jsx
const visibleItems = useMemo(
  () => items.filter(item => item.name.includes(keyword)),
  [items, keyword]
);
```

在这个例子里，切换主题可以复用上次的结果；输入新字符会改变 `keyword`，仍要重新筛选。优化后用相同的数据量重复同一次操作，对比输入到画面更新的耗时。
