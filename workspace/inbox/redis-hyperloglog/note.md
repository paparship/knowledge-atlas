HyperLogLog 是一种以少量内存估算不同元素数量的数据结构，适合海量数据的去重计数。

## 什么时候用

例如活动首页展示「今日参与人数」：同一用户参与多次只计一人，用户规模很大，展示数据允许少量误差，此时可以使用 Redis HyperLogLog。

类似场景包括每日独立访客数（UV）、活动参与人数、不同设备数量；用户 ID 即使数值很大且稀疏，也可以直接加入统计。

## 怎么用

按日期或活动建立统计键，每次用户参与时加入用户 ID，展示时读取估算人数：

```text
PFADD activity:2026-11-15:users user-101
PFADD activity:2026-11-15:users user-102
PFADD activity:2026-11-15:users user-101

PFCOUNT activity:2026-11-15:users
```

同一个用户 ID 重复加入不会重复累计；上述数据只有两个不同用户，小规模情况下通常返回 2。

## 使用特点

- **省内存**：Redis 的一个 HyperLogLog 最多约占 12 KB 的统计数据空间，适合数量很大的集合。
- **近似计数**：标准误差约为 0.81%，适合展示统计；账务结算、精确名额控制等场景应采用精确计数方案。
- **只保留统计特征**：可以估算人数，但不能列出参与者、判断某个用户是否参与，也不能删除某个用户的贡献。
